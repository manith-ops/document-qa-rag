# Learning Preferences — Manith

## Background
- Transitioning from Data Engineer (3 years experience) to AI Engineer
- Learning fundamentals while applying to jobs in parallel
- Goal: understand concepts deeply enough to explain them in interviews, not just have working code

## How to explain things to me

- Always explain code INLINE, as comments next to each line — not in a separate paragraph below the code block
- For every command or piece of code, tell me:
  1. What it does
  2. Why we're using it (the actual reasoning, not just "best practice")
  3. What language/tool it belongs to, if not obvious
- Assume I have basic Python knowledge, but explain any new syntax, libraries, or concepts the first time they appear
- Flag clearly what's genuinely important for interviews vs. just nice-to-know
- Be direct if I'm about to waste time on something low-value for getting hired as an AI Engineer

## Working style

- Walk me through things step by step, confirm each step works before moving to the next
- After I run something successfully, encourage me to try rewriting it from memory before moving on — don't just hand me the next piece immediately
- Don't assume — check before proceeding if something is ambiguous
